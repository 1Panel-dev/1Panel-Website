1Panel v2.5.0 を公開しました。本バージョンでは GPU 管理、vLLM 管理、モデルサービスを全面的に作り直し、ローカルモデルの準備、デプロイ、監視、ベンチマーク、そして AI Gateway 経由での公開まで、導入の全フローを一つにつなげました。仮想マシン管理はコミュニティ版のユーザーに完全開放され、運用レポートはプロフェッショナル版のユーザーに開放されています。あわせて 1Panel MCP サービスの管理、コンテナイメージの更新検出、一括アップグレードも追加し、サーバー管理体験を継続的に改善しています。

2026 年 11 月 11 日、次世代の Linux サーバー管理パネル 1Panel は v2.5.0 を正式にリリースしました。

1Panel v2.5.0 は**ローカルモデル導入体験の向上**に焦点を当てています。**GPU 管理、モデルの準備、モデルのデプロイ、モデルサービス、ベンチマーク、そして AI Gateway を通じた Token サービスの提供**までを一つのループとして接続します。新バージョンでは、AI サーバー上でローカルモデルをすばやくデプロイおよび管理でき、環境チェック、デプロイ設定、稼働監視をパネル上で完結できるため、複数のツールを行き来する手間を減らせます。

同時に、1Panel v2.5.0 は仮想マシン管理機能をコミュニティ版ユーザーに完全開放し、運用レポート機能をプロフェッショナル版ユーザーに開放しました。さらに 1Panel MCP サービスの管理、コンテナイメージの更新検出と一括アップグレードといった実用的な機能を追加し、サーバー管理体験を継続的に改善しています。

既存のユーザーは、パネル右下の「アップデートを確認」をクリックしてオンラインアップグレードを実行できます。完全な変更内容は [v2.5.0 リリース](https://github.com/1Panel-dev/1Panel/releases/tag/v2.5.0)をご覧ください。

**コミュニティの皆さまからの継続的なフィードバックとご支援に感謝いたします。1Panel は、より効率的で安全、そしてインテリジェントな Linux 運用体験をともに築いていくことを楽しみにしています。**

## ハイライト

### GPU 管理を全面的に刷新

ローカルモデルをデプロイする前に、GPU が正しく認識されているか、ドライバーとコンテナランタイムが準備できているかを確認する必要があります。1Panel v2.5.0 は GPU 管理を全面的に作り直し、デバイス情報、環境状態、リアルタイム監視と履歴監視を一つの画面に集約しました。これにより、現在のデバイスの利用条件と稼働状況を容易に把握できます。

NVIDIA デバイスでは、パネル上でドライバーと NVIDIA Container Toolkit の状態を確認でき、インストールと設定のガイドも参照できます。他ベンダーのデバイスでは、パネルが該当する環境診断情報を提供し、どの準備作業が残っているかを判断できます。

モデル稼働後は、GPU 使用率、メモリ使用量、温度、消費電力などの指標をリアルタイムで確認でき、履歴グラフから負荷の変化を観察できます。デバイスごとに利用可能な指標が表示されるため、リソース不足や高負荷の原因調査、デプロイ調整の参考にできます。

### 厳選モデル、モデルのダウンロード、vLLM Recipes の連携

オープンソースモデルが増え続ける中で、「どのモデルを選ぶか」「どこからダウンロードするか」「起動パラメータをどう設定するか」は、デプロイ前に解決すべき課題です。

1Panel v2.5.0 は、厳選モデル、モデルのダウンロード、vLLM Recipes を連携させ、モデルの準備をより明確な情報に基づいて行えるようにしました。厳選モデル一覧でモデルの仕様、用途、重みのサイズなどを確認し、そのままダウンロードの流れに進んでデプロイに必要なローカルファイルを準備できます。ダウンロードタスクとローカルのモデルファイルは一元管理でき、後から探して再利用しやすくなります。

起動設定の参考が必要なモデルでは、vLLM Recipes が提供するデプロイ設定例を確認し、対象ハードウェア、モデルバージョン、実行環境に合わせてパラメータを調整できるため、設定をゼロから組み立てる手間を減らせます。

### vLLM 管理を刷新し、デプロイ設定と稼働監視をわかりやすく

モデルファイルの準備ができたら、次はモデルを安定して稼働させます。1Panel v2.5.0 は vLLM 管理モジュールを全面的に作り直し、インスタンス作成、デプロイ設定、稼働監視といった工程を整備しました。選択したモデルとハードウェア環境に沿ってデプロイ作業を進められます。インスタンス作成時には、実行イメージ、モデルファイル、起動テンプレートを選択し、GPU とモデルの起動パラメータを設定できます。

インスタンス稼働後は、モデルの状態とログをまとめて確認でき、監視ページでリクエスト数、Token スループット、応答遅延などの指標を確認できます。GPU リソースの使用状況とあわせてサービスの負荷を観察しやすくなり、その後のデプロイパラメータ調整の根拠になります。

### ローカルモデル、パブリッククラウド、自建 AI Gateway アカウントの一元管理

実際の運用では、ローカルにデプロイしたモデル、パブリッククラウドのモデル、自建の AI Gateway が同時に存在することがよくあります。1Panel v2.5.0 は「モデルサービス」モジュールを全面的に作り直し、ローカルのモデルサービス、パブリッククラウドのモデルアカウント、自建 AI Gateway のモデルアカウントを一元管理できるようにしました。これにより、異なる提供元のモデルサービスを確認・保守しやすくなります。

提供元ごとに接続アドレスとアクセス認証情報を設定し、アカウント配下のモデル一覧を確認して接続を検証できます。デプロイと接続が完了すると、サービス情報と利用可能なモデルがより明確になり、その後の利用やベンチマークのための統一された選択入口になります。

### 複数のベンチマークプリセットを用意

モデルを公開した後は、実際の負荷での挙動を把握する必要があります。たとえば、最初の Token が返るまでの時間、継続的な出力速度、並列数を上げたときのスループットなどです。1Panel v2.5.0 はモデルサービスのベンチマーク機能を提供し、対象のサービスとモデルを選択したうえで、簡易検証、標準テスト、完全テストといったプリセットを使って目的に応じた性能テストを実行できます。

リクエスト長、出力長、並列数を調整でき、最初の Token までの時間（TTFT）、リクエスト遅延、Token スループットなどの結果を確認できます。同じプリセットで異なるデプロイ設定をテストすることで、パラメータ変更による変化を把握しやすくなり、リソース計画やサービスのチューニングに役立ちます。

## その他の新機能

- **仮想マシン** — 仮想マシン管理機能をコミュニティ版ユーザーに開放。
- **概要** — GPU 状態ビューと vLLM の Token スループット監視を追加し、複数のディレクトリショートカットに対応。
- **エージェント** — DeepSeek Harness と OctoP をサポート。
- **MCP 管理** — 1Panel MCP サービスの管理機能を追加。
- **ウェブサイト** — パフォーマンス調整でリバースプロキシのタイムアウトを設定可能に。
- **証明書** — 発行済み証明書を複数のローカルディレクトリへ一度に配布でき、自己署名ルート証明書をインポート可能に。
- **コンテナ** — コンテナディレクトリへのファイル一括アップロードに対応。
- **コンテナ** — イメージの更新検出と状態表示を追加し、コンテナ一覧で一括アップグレードに対応。
- **コンテナ** — Docker Hub のリモートイメージ検索に対応。
- **コンテナ** — NVIDIA GPU ランタイム設定のスイッチを追加。
- **計画タスク** — URL アクセスタスクで User-Agent リクエストヘッダーを設定可能に。
- **リソース同期** — PHP 拡張テンプレートをノード間で同期可能に。
- **運用レポート（X-Pack）** — 運用レポート機能をプロフェッショナル版ユーザーに開放。
- **マルチノード（X-Pack）** — 既存のインストールパッケージを使ったノードのインストールとアップグレードに対応。

## 改善点

- **アプリストア** — ローカルアプリ同期で子ノードを連携可能に。イメージプレフィックスを個別に設定・有効化でき、同期時のリソースリクエストを削減。
- **エージェント** — MiniMax Flash のモデル一覧と既定設定、および DeepSeek の既定モデル名を更新。
- **ウェブサイト** — Brotli 設定がまだ反映されていない場合の状態表示を改善。
- **実行環境** — 更新時にイメージの取得完了を待ってから既存コンテナを停止するようにし、イメージ取得によるサービス停止時間を短縮。
- **データベース** — データベースのユーザー名とパスワードの検証ルールを統一。
- **コンテナ** — 作成日時による並び替えに対応し、並び替え解除時に既定の順序へ戻すように。また、一覧が長時間読み込み状態になる問題を緩和。
- **ファイル** — 名前変更時の Esc キーとキャンセル操作の処理を改善し、機密ファイル操作の送信元検証と履歴の送信元追跡を強化。
- **ターミナル** — ダークモードでのターミナルショートカットの枠線表示を改善。
- **インターフェース設定** — タスクログと削除確認ダイアログを統一し、Enterprise Edition のログインページ背景を更新。
- **ログ監査** — 信頼済みプロキシ利用時のクライアント IP 記録とログイン情報の保持を改善。
- **パネル設定** — 無効化済み API キーの削除に対応し、バックアップストレージと HTTPS プロキシ証明書の検証を改善。カスタム CA 証明書にも対応。
- **システム** — テーブルのツールチップ位置を統一し、1 ページあたりの最大件数を引き上げ、テーブルのレスポンシブレイアウトを改善。
- **システム** — 期限切れセッションと認証情報の利用に対するアクセス制限を強化し、外部リソース要求の TLS 証明書検証を改善。Markdown と HTML の解析依存関係を更新。
- **マルチノード（X-Pack）** — ノード間の SFTP アップロード速度を改善し、ノードデータ同期の再試行時間を延長。

## 不具合修正

- **アプリストア** — 「+」または「-0」で始まる数値パスワードが、アプリのインストールやアプリパラメータ変更時に書き換えられる問題を修正。
- **アプリストア** — アプリのアップグレード時に環境変数の値が書き換えられる問題、および配信終了したバージョンのアプリをアップグレードできない問題を修正。
- **アプリストア** — ノードプロキシ経由でアクセスした際のアプリアイコンのリダイレクト異常、リソースキャッシュの更新、PHP 実行環境バージョンの選択肢に関する問題を修正。
- **エージェント** — Hermes の WeChat チャネル設定時にモジュール不足が表示され、QR コードが表示されない問題を修正。
- **エージェント** — OpenClaw アップグレード後の Feishu プラグインの互換性問題を修正し、旧版の Feishu 設定を保持するように。
- **ウェブサイト** — PHP 実行環境の変更がサブサイトに同期されない問題を修正。
- **実行環境** — プロジェクトのターミナルでコンテナが見つからず接続できない問題を修正。
- **データベース** — 管理ツールの入口がアプリのカスタム Web アクセスアドレスを使用しない問題を修正。
- **コンテナ** — コンテナ編集後に一覧へ戻ると検索条件が失われる問題、およびアプリインスタンス名に大文字が含まれるとログをクリーンアップできない問題を修正。
- **ファイル** — 名前変更時に同名の対象ファイルを直接上書きする問題、保存先が選択したディレクトリの外になる可能性がある問題、tar 圧縮コマンドの引数インジェクションの問題を修正。
- **ターミナル** — ノード追加後に自動キーが正しく表示されず、接続時に SSH パスワードの入力が必要になる問題を修正。
- **計画タスク** — スクリプトライブラリの同期で古いリソースキャッシュが使われる問題を修正。
- **ログ監査** — ウェブサイトの PHP バージョン切り替えや PHP 実行環境の削除時に、操作ログがリソース名ではなくリソース ID を表示する問題を修正。
- **パネル設定** — セキュリティ入口を再度有効化するとパネルにアクセスできなくなる問題、およびバックアップアカウントの名前検索が異常になる問題を修正。
- **システム** — `1pctl` コマンドでのパスワード変更がパスワード複雑性設定に従わない問題を修正。
- **システム** — 夏時間終了後、重複する時間帯での時刻同期によりシステム時計が 1 時間戻る問題を修正。
- **WAF（X-Pack）** — ウェブサイト設定を開く際のエラー、およびコミュニティ版子ノードの基本 API が許可されない問題を修正。
- **ウェブサイト監視（X-Pack）** — リクエストログの統計エラーを修正。
